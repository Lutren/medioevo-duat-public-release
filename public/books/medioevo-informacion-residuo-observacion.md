# MEDIOEVO: Informacion, Residuo y Observacion

Status: `PUBLIC_SAFE_MANUSCRIPT_DRAFT / SHORT_BOOK / NO_GUMROAD_ACTION`

Autor: Luis Rene Gonzalez Lopez / Lutren / Tyr

Este libro corto presenta una version publica y de bajo claim de la teoria de
informacion MEDIOEVO. No contiene formulas privadas completas, notebooks,
calibracion propietaria, datasets reales, runtime Claudio/Wabi-Sabi,
DUAT/GEODIA interno, libros completos, RPG/TCG ni prompts internos.

## 1. La informacion no llega a un vacio

Un sistema no observa desde cero. Observa desde un estado.

Ese estado incluye memoria, cansancio, decisiones pendientes, contradicciones,
permisos, herramientas disponibles, expectativas y evidencia ya verificada. Por
eso la misma entrada puede producir claridad en un sistema y ruido en otro.

MEDIOEVO llama residuo al costo que queda cuando una entrada no se integra:
pendientes sin cierre, claims sin prueba, fuentes sin ficha, acciones sin
evidencia y decisiones que se repiten porque nunca fueron externalizadas.

La pregunta practica no es "cuanta informacion tengo?". La pregunta es:

```text
Cuanta informacion usable puede absorber este sistema en su estado actual?
```

## 2. Residuo

R es una lectura operativa del residuo acumulado. No es una verdad universal ni
una metrica clinica. En el uso publico de MEDIOEVO, R sirve para ordenar trabajo
con agentes, proyectos largos y superficies de publicacion.

R sube cuando:

- hay demasiados ciclos abiertos;
- se mezclan capas privadas y publicas;
- se repiten decisiones sin evidencia nueva;
- se copian fuentes sin origen;
- se publican claims mas fuertes que las pruebas;
- el agente ejecuta antes de clasificar riesgo.

R baja cuando:

- una tarea cierra con prueba;
- una decision queda registrada;
- una fuente obtiene ficha;
- un riesgo queda en REVIEW o BLOCK;
- el siguiente paso se vuelve pequeno, reversible y medible.

El residuo no es fracaso. Es una senal de integracion pendiente.

## 3. Phi_eff

Phi_eff es la eficiencia con la que un sistema convierte entrada en salida util:
entendimiento, decision, artefacto o cierre.

Cuando R es bajo, una pagina de contexto puede bastar. Cuando R es alto, cien
paginas pueden empeorar el trabajo. El sistema ya no absorbe; amplifica ruido.

Por eso MEDIOEVO prefiere handoffs, fingerprints, logs y mapas de decision antes
que conversaciones infinitas. La continuidad no se logra cargando todo. Se logra
externalizando estado.

## 4. Jamming

Jamming ocurre cuando mas informacion reduce la capacidad de actuar.

En un proyecto con agentes, jamming se ve asi:

- cada agente reabre el plan;
- nadie sabe que esta probado;
- se mezclan productos, canon, research y privado;
- el usuario pide cierre y el sistema genera mas teoria;
- el repo parece avanzar, pero no hay tests ni artefactos verificables.

La salida no es abrir otra feature. La salida es cerrar:

```text
observar -> documentar -> verificar -> actuar -> handoff
```

## 5. Observacion antes de accion

La regla publica central es simple: evidencia antes de accion.

Un agente que toca archivos, cuentas, despliegues o pagos necesita saber:

- que objetivo real persigue;
- que evidencia existe;
- que es inferencia;
- que no sabe;
- que esta bloqueado;
- que accion es reversible;
- que prueba demostrara cierre.

ActionGate resume esa decision:

- APPROVE: local, reversible, sin secretos, con evidencia.
- REVIEW: requiere humano, red, credenciales, licencia, publicacion o alto impacto.
- BLOCK: destructivo, exfiltra datos, toca privado o publica material protegido.

## 6. El valor publico de MEDIOEVO

La version publica de MEDIOEVO no vende acceso crudo al nucleo privado. Publica
metodos, plantillas y demos sinteticos que ayudan a trabajar mejor:

- scanners de seguridad local;
- compresores de contexto;
- handoffs reconstruibles;
- claim reviewers;
- source cards;
- WitnessLog;
- templates para releases;
- DUAT como superficie visual publica.

Lo privado queda protegido: libros no publicados, RPG/TCG, canon completo,
runtime interno, prompts crudos, datasets reales, calibracion y formulas no
liberadas.

## 7. Tres prompts como puerta de entrada

Los tres prompts gratuitos de esta campana son una puerta simple:

1. Scanner de seguridad local para IA.
2. Ahorro de tokens extremo.
3. Handoff de memoria persistente.

Juntos resuelven un problema comun: los agentes trabajan mejor cuando el estado
esta claro, los riesgos estan nombrados y el cierre queda guardado.

## 8. Cierre

MEDIOEVO no empieza con la promesa de una inteligencia perfecta. Empieza con una
disciplina mas humilde y mas util:

```text
observar el estado,
reducir residuo,
actuar con evidencia,
y dejar continuidad para el siguiente operador.
```

Los datos persisten. El operador no. Un buen sistema respeta esa asimetria.
